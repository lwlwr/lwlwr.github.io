# 公开项目展示原则

更新于 2026-10-23（北京时间）。

## 证据层级

| 类型 | 可以支持的表述 | 不能自动支持 |
| --- | --- | --- |
| 简历和历史笔记 | 工作范围的本人记录、历史结果线索 | 独立验证、公开复现、企业披露授权 |
| 可运行工具和测试 | 该代码在指定输入下的行为 | 历史训练发生、历史模型收益 |
| 日志与 checkpoint | 特定配置运行及更新的证据 | 泛化能力或公平对照 |
| 固定隔离集逐题结果 | 给定协议下的模型比较 | 未测试任务和生产环境收益 |
| 目标设备验收 | 给定设备、版本及协议的结果 | 所有硬件均可部署 |

主页的经历与日期依据现有简历核对；不是第三方雇佣认证。最新简历优先于旧主页的占位日期。历史笔记用于限定结果口径，不把笔记整理时间当作项目发生时间。

## 企业内容边界

只介绍本人职责及通用技术方法。不上传内部代码、数据、日志、模型、权重、业务样本、内部链接、客户信息及访问凭据。现有简历不构成企业材料的开源许可。需要公开的独立实现应从公开许可资源与自行生成样例开始，并标明与实习项目的区别。

## 发布数字前的最低要求

记录任务、模型、数据来源与许可、划分、样本量、评测定义、解码配置、代码版本、逐样本结果和基线；明确个人贡献和测试限制。有随机性时报告多次实验及不确定性。

不把“脚本执行结束”“参数发生更新”“模型能力提高”混为一谈；不把导出成功当作实机部署通过。
