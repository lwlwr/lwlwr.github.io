# Countdown GRPO：项目说明与复现方案

## 历史实践范围

2026.01–2026.02，个人项目。根据现有简历与项目笔记，使用 Qwen2.5-3B-Instruct 探索 RTX 4090 24GB 单卡上的 GRPO：
- 数据预处理、任务正确性及格式奖励、rollout 采样、训练监控与评测。
- 跟踪奖励、成功率及输出长度，排查长度漂移和格式异常。
- 调试 optimizer CPU offload、响应长度及未完成样本过滤等配置。

这些是材料中的个人工作陈述；本仓库尚未公开历史训练代码和日志，不能据此独立审计每项实现。

## 结果边界

历史简历及项目笔记记录准确率 4.3% → 60.4%。目前缺少对应数据划分、评测样本量、逐题预测、解码参数及原始日志，**不将其作为公开复现成绩**。格式合法率和峰值显存的历史数字也暂不作为结果展示。

本次没有训练模型，也没有补造日志、训练曲线或 checkpoint。

## 已提供的可运行补充

[表达式评测器及运行说明](../tools/README.md)于 2026-10-23 新增，用纯合成输入检查：
- 只接受整数、括号和加减乘除；拒绝函数调用、属性访问、幂运算等。
- 数字的多重集合必须与题目一致，每个给定数字恰用一次。
- 用有理数精确计算，不用浮点近似判等。
- 分开报告语法合法、数字使用合法和最终正确。

该工具只评测已抽取的表达式，不生成答案、不计算 GRPO loss、不替代模型训练。它的规则不一定等于历史 reward，不能直接用于验证历史成绩。

## 待执行的公开复现方案

| 环节 | 必须保存的证据 |
| --- | --- |
| 数据 | 来源及许可、预处理版本、按题目规范化去重后的固定划分、样本数和文件 SHA256 |
| 模型 | 基础模型 revision、tokenizer、训练及评测代码 commit、依赖锁定 |
| 对照 | 未训练基座 vs GRPO checkpoint；完全相同的 held-out 题目、提示词及解码配置 |
| 训练 | seed、组大小、温度、长度上限、学习率、KL 系数、更新步数、checkpoint 对应关系 |
| 奖励 | 格式与正确性定义、重复数字、除零、截断及奖励投机样例 |
| 更新 | 非零梯度、参数或 adapter 差异、保存后重新加载检查 |
| 评测 | 每题预测、格式有效率、最终正确率、分子分母；多随机种子和不确定性 |
| 资源 | 峰值 allocated / reserved 显存、GPU 型号、wall time、吞吐及 offload 配置 |

采用 base/GRPO 配对比较；如改奖励、长度或过滤策略，逐项消融，保持其他配置相同。截断样本不能从评测分母静默删除。相同数字集合与目标的变体不能跨训练验证集泄漏。

## 应能解释的技术问题

- 为什么组内全同奖励会使相对优势缺少信号？
- 格式奖励是否掩盖了任务正确性？奖励与独立 evaluator 是否一致？
- CPU offload 节约什么显存，又付出什么吞吐代价？
- 未完成样本过滤是否改变训练分布？长题是否更容易被排除？
